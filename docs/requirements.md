# SabakanOS 要件定義

- 版: 0.1.0（ドラフト）
- 最終更新: 2026-11-13
- 対象リリース: SabakanOS 0.1.0-dev（開発初期）
- 参照資料: コンセプト調査レポート（推奨案「SabakanOS Dev」）

## 1. 目的

本書は SabakanOS の機能要件・非機能要件・マイルストーンを定義し、実装レーン（A〜D）とドキュメント／CI／リリース／ライセンス遵守レーン（E）の間の合意事項を明文化するものです。

### 1.1 背景

軽量ディストリビューション（Alpine、Void、Arch など）は日本語デスクトップを標準では提供していません。日本語環境を整えるには、ロケール、入力メソッド、フォント、キーボードレイアウトを個別に導入する必要があり、初回セットアップの負担が大きくなります。

SabakanOS はこの負担をなくし、「軽量であること」と「日本語が最初から使えること」を両立させます。

### 1.2 対象ユーザー

| ペルソナ | 課題 | 本 OS が提供する価値 |
|----------|------|----------------------|
| 個人開発者 | 開発機のセットアップに時間を取られる | 日本語環境とツールチェーンが揃った状態でインストール完了 |
| インフラ／バックエンドエンジニア | 古い検証機や VM に軽量環境が欲しい | 低リソースで動作する再現可能なビルド |
| 教育・検証用途の運用者 | 配布物のライセンス確認が煩雑 | ライセンス一覧とソース提供手段を同梱 |

### 1.3 スコープ

**対象**

- カーネル、ブートローダー、ルートファイルシステム、ISO イメージのビルド
- 日本語環境（ロケール、時刻、キーボード、IME、フォント）の標準搭載
- ビルドの自動検証（CI）とリリース成果物の生成
- 同梱 OSS のライセンス遵守とソース提供

**対象外**

- 独自パッケージリポジトリの本番運用（設計のみ定義）
- デスクトップ環境の独自開発（既存 OSS の組み合わせで構成）
- ARM64 の実機サポート（設計上の考慮のみ）
- 商用サポート、SLA

## 2. 機能要件

優先度は MoSCoW（M: 必須 / S: 重要 / C: 可能なら / W: 今回は対象外）です。担当レーンは実装レーン（A〜D）を指し、レーン E は要件定義・検証・ドキュメントを担当します。

### 2.1 ビルドと成果物

| ID | 要件 | 優先度 | 受け入れ条件 |
|----|------|--------|--------------|
| FR-001 | `make build-kernel` で Linux カーネルをビルドできる | M | `build/linux-6.18.63/arch/x86/boot/bzImage` が生成され、終了コードが 0（クロスコンパイラがない環境では `.config` の準備完了で正常終了） |
| FR-002 | `make build-rootfs` でルートファイルシステムを構築できる | M | `rootfs/init`、`rootfs/bin/sh`、`rootfs/etc/passwd`、`rootfs/etc/hostname` が存在する |
| FR-003 | `make build` / `make all` でカーネルとルートFSを一括ビルドできる | C | 上記 2 ターゲットを順に実行した結果と同一の成果物になる（現状 `all` は `help` の別名） |
| FR-004 | ISO 生成スクリプトで BIOS / UEFI 両対応のハイブリッド ISO を生成できる | M | `scripts/build-iso.sh` が `build/sabakanos.iso` を生成し、QEMU で起動してシェルに到達する |
| FR-005 | カーネル成果物を ISO 生成スクリプトが参照できる場所に配置する | S | `build/linux-6.18.63/arch/x86/boot/bzImage` が `build/kernel` など候補パスにコピーされる（現状は手動、自動化は未実装） |
| FR-006 | `make clean` でビルド成果物を削除できる | S | `build/`、`rootfs/`、`tool/` が削除される |
| FR-007 | `make help` でターゲット一覧を表示する | C | 未指定時にヘルプが表示され、終了コード 0 |

### 2.2 ブートとインストール

| ID | 要件 | 優先度 | 受け入れ条件 |
|----|------|--------|--------------|
| FR-010 | Limine で BIOS 起動できる | M | QEMU（`-boot d`）で起動する |
| FR-011 | Limine EFI で UEFI 起動できる | M | OVMF を使った QEMU 起動で起動する |
| FR-012 | Live 環境として USB メモリから起動できる | M | Live USB を作成し実機または VM で起動できる |
| FR-013 | ISO を USB に書き込む手順が文書化されている | S | `dd` のコマンド例と警告が README に記載されている（`make install` は未実装） |
| FR-014 | `sabakan-install` でディスクへインストールできる | S | 対話形式でディスク・ホスト名・ユーザーを指定し、再起動後にログインできる（未実装。現状は手動展開） |
| FR-015 | ルートFSを任意ディレクトリへ展開できる | S | `cp -a rootfs/. <dir>` 相当の手順が文書化されている |
| FR-016 | シリアルコンソールで操作できる | C | `console=ttyS0` 指定で QEMU の `-nographic` から操作できる |

### 2.3 日本語環境

| ID | 要件 | 優先度 | 受け入れ条件 |
|----|------|--------|--------------|
| FR-020 | 既定ロケールが `ja_JP.UTF-8` である | M | ログイン直後の `locale` が `LANG=ja_JP.UTF-8` を返す |
| FR-021 | タイムゾーンが `Asia/Tokyo` である | M | `date` が JST を表示する |
| FR-022 | 仮想コンソールのキーマップが `jp106` である | M | `localectl status` または `/etc/vconsole.conf` が `jp106` |
| FR-023 | Mozc による日本語入力が利用できる | S | IBus または Fcitx5 経由で「日本語入力のテスト」を変換できる |
| FR-024 | 日本語フォント（Noto Sans CJK JP）が導入されている | M | `fc-match "Noto Sans CJK JP"` が Noto を返す |
| FR-025 | 日本語の man ページまたはヘルプが参照できる | C | `man ls` 等で日本語表示または英語フォールバックが動作する |
| FR-026 | 端末で日本語が文字化けしない | M | UTF-8 環境で日本語ファイル名の作成・表示ができる |

### 2.4 システム管理

| ID | 要件 | 優先度 | 受け入れ条件 |
|----|------|--------|--------------|
| FR-030 | apk でパッケージの導入・削除・更新ができる | M | `apk add` / `apk del` / `apk upgrade` が成功する |

| FR-033 | SSH サーバを導入できる | C | 導入後にリモートからログインできる |
| FR-034 | 開発ツールチェーンを導入できる | S | gcc、make、git、python3 が動作する |
| FR-035 | コンテナランタイムを導入できる | C | podman または docker で `hello-world` が動作する |
| FR-036 | アップデートとロールバックができる | C | `sabakan-upgrade` で更新でき、直前の状態に戻せる |

### 2.5 ドキュメント・CI・リリース・ライセンス（レーン E）

| ID | 要件 | 優先度 | 受け入れ条件 |
|----|------|--------|--------------|
| FR-040 | README にビルド・インストール・日本語設定手順が記載されている | M | 記載手順のみで ISO 生成まで到達できる |
| FR-041 | 要件定義・ライセンス方針・ソース提供フローを `docs/` に置く | M | 3 ファイルが存在し、相互に参照している |
| FR-042 | CI で `make build-kernel` と `make build-rootfs` を自動実行する | M | push / PR でワークフローが起動し、成功する |
| FR-043 | CI でドキュメントとライセンスファイルの存在を検証する | S | 必須ファイル欠落時にジョブが失敗する |
| FR-044 | タグ push で ISO とソースバンドルを Release に添付する | S | `v*.*.*` タグで Release が作成される |
| FR-045 | `iso/COPYING` に同梱 OSS のライセンス一覧を記載する | M | 全同梱コンポーネントのライセンスとポインタが記載されている |
| FR-046 | GPL / LGPL 対象物の対応ソース提供手段を文書化する | M | `docs/source-flow.md` に取得・検証・保管の手順がある |
| FR-047 | 秘密情報をリポジトリに含めない | M | `.gitignore` により秘匿ファイルが除外され、CI で検出されない |

## 3. 非機能要件

| ID | 項目 | 目標値 | 検証方法 |
|----|------|--------|----------|
| NFR-001 | 起動時間 | SSD 環境で 15 秒以内（CLI 構成） | QEMU または実機で `systemd-analyze` 相当の計測、シリアルログのタイムスタンプ |
| NFR-002 | アイドルメモリ使用量 | CLI 300MB 以下 / 軽量デスクトップ 500MB 以下 | `free -m` を起動 5 分後に計測 |
| NFR-003 | ISO サイズ | 最小構成 1GB 以下 / デスクトップ構成 2GB 以下 | `ls -lh iso/*.iso` |
| NFR-004 | ビルド時間 | CI（4 コア）でカーネル 40 分以内、ルートFS 20 分以内 | GitHub Actions のジョブ実行時間 |
| NFR-005 | 再現性 | 同一コミット・同一設定から同一ハッシュの成果物を生成（タイムスタンプ依存を除く） | 2 回ビルドして `sha256sum` を比較 |
| NFR-006 | セキュリティ | パッケージ署名検証、SSP / PIE 有効、`/tmp` の適切なパーミッション | ビルド設定のレビューと `checksec` による確認 |
| NFR-007 | ライセンス遵守 | 同梱バイナリの 100% についてライセンスとソース取得手段を特定 | `docs/source-flow.md` のマニフェスト突合 |
| NFR-008 | ドキュメント品質 | README のみでビルドとインストールが完了できる | 新規環境での通し検証（四半期に 1 回） |
| NFR-009 | 対応アーキテクチャ | x86_64 は必須、ARM64 は設計上の考慮 | ビルド設定の分離状況をレビュー |
| NFR-010 | CI 信頼性 | main ブランチの CI 成功率 95% 以上 | Actions の実行履歴 |
| NFR-011 | ポータビリティ | ビルドホストは Ubuntu 24.04 / Debian 12 で再現 | CI の実行環境と README の手順の一致 |
| NFR-012 | 監査性 | リリースごとに SBOM とソースマニフェストを保管（3 年以上） | リリース成果物の添付状況 |

## 4. 制約と前提

| 区分 | 内容 |
|------|------|
| ライセンス制約 | プロジェクト本体は MIT。同梱 OSS は各ライセンスに従う。GPL と非互換ライセンス（例: CDDL のみのコード）を同一バイナリに混在させない |
| 配布制約 | GPL / LGPL 対象バイナリを配布する場合、対応ソースの提供義務が発生する（[`license.md`](license.md)） |
| 技術的前提 | ビルドホストは Linux x86_64（macOS は `gmake` とクロスコンパイラが必要）。ネットワーク接続がある |
| リポジトリ前提 | `Makefile`、`scripts/`、`boot/`、`config/`、`rootfs/`、`packages/` は実装レーンが所有し、レーン E は変更しない |
| 運用前提 | リリースは Git タグで管理し、CI が成果物を生成する |
| 除外事項 | 商用サポート、法務判断、特定ベンダーへの最適化は本要件の対象外 |

## 5. アーキテクチャ概要

```text
┌────────────────────────────────────────────────┐
│ ISO イメージ（build/sabakanos.iso）             │
│  ├─ /boot/kernel          ← build/kernel        │
│  ├─ /boot/initramfs.img   ← build/initramfs.img │
│  ├─ /boot/limine.cfg      ← boot/limine.cfg     │
│  └─ /EFI/BOOT/BOOTX64.EFI ← Limine (EFI)        │
└────────────────────────────────────────────────┘
        ▲                      ▲
        │ scripts/build-iso.sh │ make build-rootfs
        │                      │
   ┌────┴─────┐         ┌──────┴──────┐
   │ scripts/ │         │  rootfs/    │
   └────┬─────┘         └──────┬──────┘
        │                      │
   ┌────┴─────┐         ┌──────┴──────┐
   │ boot/    │         │ config/     │
   └──────────┘         └─────────────┘
```

| 層 | 役割 | 所有 |
|----|------|------|
| `config/` | カーネル設定、Buildroot defconfig、パッケージ一覧 | 実装レーン |
| `boot/` | Limine の設定（`limine.cfg`） | 実装レーン |
| `scripts/` | カーネル・ルートFS・ISO のビルド、QEMU 起動 | 実装レーン |
| `packages/` | APKBUILD 形式のパッケージ定義 | 実装レーン |
| `docs/`、`.github/workflows/`、`iso/COPYING` | 要件、ライセンス遵守、CI、リリース | レーン E |

## 6. レーン間インタフェース契約

ドキュメントと CI が依存するビルド入口の契約です。実装レーンはこの名前と出力先を維持してください。名前を変更する場合は、レーン E のドキュメントと CI を同時に更新する必要があります。

| 入口 | 状態 | 入力 | 出力 | 所有 |
|------|------|------|------|------|
| `make help` | 実装済み | — | 標準出力にターゲット一覧 | レーンA |
| `make build-kernel` | 実装済み | `config/kernel-defconfig` | `build/linux-6.18.63/arch/x86/boot/bzImage`（クロスコンパイラなしの場合は `.config` のみ） | レーンA |
| `make build-rootfs` | 実装済み | `config/buildroot-defconfig`、`config/packages.txt` | `rootfs/`（`init`、`bin/sh`、`etc/passwd`、`etc/hostname`） | レーンA |
| `make clean` | 実装済み | — | `build/`、`rootfs/`、`tool/` の削除 | レーンA |
| `scripts/build-iso.sh` | 実装済み | `boot/limine.cfg`、カーネル、Limine 本体 | `build/sabakanos.iso` | レーンB |
| `scripts/run-qemu.sh` | 実装済み | `build/sabakanos.iso` | QEMU 起動（終了コード 0） | レーンB |
| `make iso` | 未実装 | — | `scripts/build-iso.sh` の呼び出しを想定 | レーンA |
| `make test` | 未実装 | — | `scripts/run-qemu.sh` の呼び出しを想定 | レーンA |
| `make install` | 未実装 | `DEVICE` / `DESTDIR` | USB 書き込みまたは展開 | レーンA／D |
| `make source-bundle` | 未実装 | ソースマニフェスト | `build/source/` 以下のソース一式 | レーンA（仕様はレーン E） |

### 6.1 既知の未接続点

現時点で、レーン間の受け渡しが手動または未実装の箇所は次のとおりです。CI と README はこの状態を前提に記述しています。

| 項目 | 現状 | 解消条件 |
|------|------|----------|
| カーネル成果物の配置 | `make build-kernel` の出力は `build/linux-6.18.63/arch/x86/boot/bzImage` だが、`scripts/build-iso.sh` は `build/kernel` などを探す | どちらかを揃える（Makefile にコピー処理を追加するか、ISO スクリプトの候補に追加する） |
| Limine 本体の入手 | `limine-bios.sys` / `limine-efi.sys` を手動で `build/limine/` に配置する必要がある | 取得手順の自動化、または同梱とライセンス表記の追加 |
| `make iso` ターゲット | 存在せず、`scripts/build-iso.sh` を直接実行する | Makefile にターゲットを追加 |
| 日本語環境の同梱 | `config/packages.txt` に IME・フォントが含まれず、`rootfs/etc` への配置も未実施 | FR-020〜FR-024 の実装 |
| `/etc/os-release` | ルートFSに未生成 | 生成処理の追加（`VERSION` と一致させる） |

### 6.2 バージョン情報の受け渡し

ISO のファイル名、`/etc/os-release`、リリースタグは同一のバージョン値を使用します。値の単一情報源はリポジトリのタグとし、レーン E のドキュメントでは `0.1.0-dev` を初期値として記載しています。

### 6.3 CI が前提とするもの

- `Makefile` がリポジトリ直下に存在する
- `make build-kernel` と `make build-rootfs` が非対話で完了する（確認プロンプトを出さない）
- カーネルは `build/linux-*/arch/x86/boot/bzImage`、ルートFSは `rootfs/` に出力される
- 失敗時は非ゼロの終了コードを返す（現状のスクリプトは、クロスコンパイラ不在や Buildroot 取得失敗を警告として扱い正常終了する）

## 8. 受け入れ基準（レーン E）

本レーンの成果物は次を満たすときに完了とします。

1. `README.md` に概要、ビルド手順、インストール手順、日本語環境設定手順、ディレクトリ構成、ライセンス表記が含まれる
2. `docs/requirements.md`、`docs/license.md`、`docs/source-flow.md` が存在し、相互参照が解決する
3. `.github/workflows/ci.yml` が `make build-kernel` と `make build-rootfs` を実行する
4. `.github/workflows/release.yml` がタグ push で ISO とソースバンドルを添付する
5. `iso/COPYING` に同梱 OSS のライセンス一覧と個別ライセンスファイルへのポインタがある
6. ドキュメントに記載されたコマンドが、実装済みターゲットの範囲でそのまま実行できる
7. 秘密情報（トークン、鍵、認証情報）が含まれていない

## 9. リスクと対応

| リスク | 影響 | 対応 |
|--------|------|------|
| GPL 対象バイナリのソース提供漏れ | 配布停止・法的リスク | リリース前チェックリストとマニフェスト突合を必須化（[`source-flow.md`](source-flow.md)） |
| カーネルビルドの依存差異で CI が不安定 | 開発速度低下 | CI の依存導入を一箇所に集約し、README と一致させる |
| 日本語フォント同梱による ISO サイズ増加 | 配布性の悪化 | サブセット化または同梱範囲の見直し（OFL の改変条件に注意） |
| Mozc 辞書のライセンス混在 | 再配布時の違反 | 辞書の出所を `docs/license.md` に記録し、同梱物を限定 |
| 実装レーンのターゲット名変更 | CI とドキュメントの破綻 | 第 6 章の契約を変更時に同時更新する運用 |
| Live USB 書き込みの誤操作 | データ消失 | README での警告強化と、`make install` 実装時の `DEVICE` 必須化・確認プロンプト |
| カーネル成果物と ISO 生成の受け渡し未接続 | ISO が生成できない | `docs/requirements.md` 6.1 の未接続点を解消し、CI の ISO ジョブを必須化 |
| 再現性の欠如（タイムスタンプ・並列ビルド） | 監査・検証の困難 | `SOURCE_DATE_EPOCH` の利用とハッシュ記録 |

## 10. 用語

| 用語 | 定義 |
|------|------|
| ルートファイルシステム | 起動後に `/` としてマウントされるファイル群。`rootfs/` に構築する |
| Live 環境 | インストールせずに USB や ISO から直接起動できる環境 |
| マニフェスト | 同梱物とそのライセンス・ソース取得先を対応付けた一覧（[`source-flow.md`](source-flow.md)） |
| 対応ソース | バイナリに対応する完全なソースコード。GPL / LGPL の提供義務の対象 |
| SBOM | Software Bill of Materials。同梱コンポーネントの一覧を機械可読形式で表したもの |
| レーン | 本プロジェクトの並行実装単位。A〜D が実装、E がドキュメント・CI・リリース・ライセンス遵守 |
